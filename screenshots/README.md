# Screenshots

Product screenshots, administrative interface showcases, and feature captures for Favorite CMS and its ecosystem.

---

## 1. Purpose & Scope

This directory stores high-quality, sanitized screenshots used across technical documentation, GitHub repository READMEs, user manuals, and release announcements.

---

## 2. Capture Standards & Quality Rules

1. **High Resolution**: Capture at 100% browser zoom on a high-DPI/Retina display where possible (e.g. 1920×1080, 1440×900, or clean component crops).
2. **Clean Framing**:
   - Crop cleanly to the relevant window, panel, or modal.
   - Do NOT include operating system taskbars, personal browser bookmarks, desktop wallpapers, or irrelevant tabs.
3. **Format**: Crisp PNG or optimized WebP. Avoid heavily compressed, blurry JPGs for text-heavy UI captures.
4. **Naming Convention**: Lowercase kebab-case indicating the view, feature, and state (e.g., `dashboard-overview-dark.png`, `plugin-manager-active.png`, `payment-gateway-settings.png`).
5. **No Ephemeral Names**: Avoid vague names such as `screen1.png`, `screenshot-final.png`, or `temp-capture.png`.

---

## 3. Mandatory Privacy & Security Sanitization

Screenshots must **NEVER** expose confidential or sensitive information:
- **Zero Real Credentials**: Blur or replace API keys, merchant passwords, access tokens, and secret hashes with dummy values (`••••••••••••••••`).
- **Zero Real Customer Data**: Use synthetic demo names ("Jane Doe", "Rahim Ahmed") and fictional emails (`user@example.com`).
- **Fictional Order Data**: Use synthetic order numbers (`ORD-2026-001`) and sample pricing.
- **Clean Domains**: Use `example.com`, `favoritecms.test`, or `localhost`.
